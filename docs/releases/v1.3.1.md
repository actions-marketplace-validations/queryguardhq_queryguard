# QueryGuard v1.3.1

A small maintenance release. **There are no changes to the linter, the report, the statuses, the exit codes or any Action input**; the analysis code is identical to v1.3.0. The one change that can affect you is the Action's runtime.

## Action now declares the Node 24 runtime

`action.yml` now says `using: 'node24'` (it was `node20`). GitHub already runs `node20` actions on Node 24, so on GitHub-hosted runners nothing changes for you. This just makes it explicit.

**If you run the Action on self-hosted runners, they must be v2.327.1 or newer.** Older self-hosted runners cannot start a Node 24 action. If you can't upgrade the runner yet, pin the previous release instead of `@v1`:

```yaml
uses: queryguardhq/queryguard@v1.3.0
```

I verified the bundle on Node 24: it type-checks, rebuilds byte-for-byte identical to the committed `dist/`, runs, and passes the full test suite against Postgres 16. I did not test an old self-hosted runner.

## Also in this release
- **CI** now runs the test suite on both Node 20 (the oldest Node the npm package supports) and Node 24 (the Action runtime).
- **Docs:** the README notes the runner requirement and shows the npm provenance badge again, now that v1.3.0 was published with an attestation. The v1.3.0 release notes are kept in the repo under `docs/releases/`.
- **Project housekeeping, no effect on users:**
  - GitHub Actions moved to `actions/checkout@v7` and `actions/setup-node@v7`, off the deprecated Node 20 action runtime.
  - CI runners are pinned to `ubuntu-24.04` ahead of GitHub's move of `ubuntu-latest` to Ubuntu 26 on 2026-10-19.
  - The release job no longer restores a dependency cache, since it holds the npm token.

## Upgrading
- **GitHub-hosted runners:** nothing to do.
- **Self-hosted runners:** make sure they are v2.327.1 or newer, or pin `@v1.3.0`.
- **npm users** (`npx queryguard`): the package differs from 1.3.0 only in the version string, the README and `action.yml` (the runtime declaration above).
