# QueryGuard v1.4.0

This release adds **production snapshots**. A lock finding has always said *what* a migration locks; with a snapshot it also says how much that matters on *your* production database. The figures come from a privacy-safe export of production's shape that is committed to your repository. The PR workflow never holds production credentials.

**Nothing changes unless you opt in.** No existing Action input, rule, status or exit code changed. Without the new `snapshot-path` input the Action runs exactly as in v1.3.1, and its report is the same.

## Highlights

### `queryguard snapshot`: production's shape, not its data
A read-only command, run by someone with production access or by a scheduled job that has it:

```bash
PGHOST=db.internal PGDATABASE=app PGUSER=queryguard_snapshot npx queryguard snapshot --label production
```

It writes `.queryguard/snapshot/`:

| File | Contents |
| :--- | :--- |
| `schema.sql` | `pg_dump --schema-only`, with owners, grants, comments, foreign-server options, user mappings and the database name removed |
| `shape.json` | Per table: estimated rows, size, scan and write counters. Per index: columns, uniqueness, validity, size, scans. Per column: null fraction, width, distinct count, correlation, and the frequencies of the most common values **without the values** |
| `workload.json` | The busiest statements from `pg_stat_statements` (top 200 by total time plus top 200 by calls), normalized, with the tables each touches |
| `redactions.json` | What was withheld or removed, and why: counts and statement IDs, never content |
| `manifest.json` | Label, time, server version, mode, status, and the SHA-256 of every other file |

- **No row data in the default mode.** The value-bearing statistics columns are never even selected. No host, port, user, password or database name is written; you name the snapshot with `--label`, and the connection comes only from the standard libpq environment.
- **Statement text is treated as hostile.** Comments are removed and utility commands dropped. If any string or numeric literal survives normalization, the whole text becomes `[redacted: literal]`, while its counters and tables are kept.
- **Rounded by default.** Every count, size and time is rounded to 2 significant figures, because exact figures can be business-sensitive. `--precision exact` turns this off.
- **Safe to run on production.**
  - Read-only transactions, with `lock_timeout` 1 s and `statement_timeout` 10 s.
  - Catalog and statistics views only. No function that would wait on a table lock is called: sizes come from page counts, not `pg_relation_size`.
  - pg_dump is the one step that takes table locks, and its wait is capped at 5 seconds.
- **Fails closed.**
  - Anything that cannot be collected is listed, and the snapshot is PARTIAL (exit `2`).
  - If `schema.sql` cannot be produced, nothing is written (exit `1`), and any previous snapshot is left untouched.
- **`--sample-window 5m`** reads `pg_stat_statements` twice and keeps the difference, so call rates reflect current traffic instead of an average since the last reset. No transaction stays open while it waits.
- **`--schema-from FILE`** takes a schema-only dump made elsewhere. With the shape function described in the security guide, the snapshot role then needs no access to any table.
- Requires PostgreSQL 14 or newer and a `pg_dump` at least as new as the server. `pg_stat_statements` (1.9+) is needed for the workload section; without it the snapshot is PARTIAL and says why.

### The Action annotates lock findings
Two new inputs, `snapshot-path` and `snapshot-max-age-days` (default `14`), also available as `--snapshot` and `--snapshot-max-age-days` on the CLI. Each lock finding gains a production column:

| Severity | Issue Type | Target Table | Production (snapshot) |
| :--- | :--- | :--- | :--- |
| 🚨 CRITICAL | `SHARE` Lock | `orders` | ~48M rows · ~14 GB · 3 query shapes · ~2,100 calls/s |

- **Severities, statuses and exit codes do not change.** The annotations are context for the reviewer.
- **An invalid snapshot makes the run INCONCLUSIVE:** a file edited after it was taken, a missing or unlisted file, or anything that fails the schema.
- **A stale or PARTIAL snapshot** gets a warning right under the status line.
- **Name resolution:** a table name that exists in more than one schema is reported as ambiguous, never guessed. A partitioned table sums its partitions.

### `queryguard snapshot inspect`
The command a security reviewer runs. It verifies every file's SHA-256 and the schema, then prints:
- the label, age, mode and status;
- the largest tables and the busiest statements;
- the full redaction report.

An invalid snapshot exits `1` and prints its problems instead.

### Full mode for PostgreSQL 18
`--mode full --allow-columns FILE` also writes `stats.sql`: `pg_restore_relation_stats` and `pg_restore_attribute_stats` calls that reproduce production's planner statistics in another PostgreSQL 18 database.
- **Allow-listed columns** get every statistic, including their most common values and histograms.
- **Every other column** gets shape only.
- **The allow-list** names one column per line. An entry that matches nothing fails the run, and `manifest.json` lists the columns whose values left production.
- **Each restore call raises if it does not apply,** instead of only warning.

### A published schema
[`schema/snapshot.v1.json`](https://github.com/queryguardhq/queryguard/blob/main/schema/snapshot.v1.json) (JSON Schema 2020-12) ships in the npm package. It rejects any field it does not define, so a statistics value column cannot appear in a valid snapshot. QueryGuard validates its own output before writing it and validates again on every load.

## Upgrading

- **Action users:** nothing to do. To use snapshots, follow the README's [Production snapshots](https://github.com/queryguardhq/queryguard#production-snapshots) section: create a read-only role, take and commit a snapshot, set `snapshot-path`, and schedule a refresh.
- **Self-hosted runners** still need v2.327.1 or newer (unchanged since v1.3.1).
- **npm users:** the package now also contains `schema/snapshot.v1.json`. The bundle grows from about 125 kB to about 360 kB, mostly the JSON Schema validator.
- **Refresh jobs** (the job that takes snapshots, not the PR check) need Node.js 20+, network access to the database, and `pg_dump` from the server's major version or newer.

## Known limitations
- **Annotations are context, not judgment.** They never change a severity.
- **Views:** statements that reach a table only through a view are not counted for that table; their references are listed as unresolved.
- **The literal check is strict.** A type length such as `varchar(10)` or a positional `GROUP BY 1` also causes redaction; the statement's counters and tables are kept.
- **Sizes and row counts are estimates.** They come from page counts and planner statistics, which VACUUM and ANALYZE keep current.
- **Full mode** does not yet include statistics for expression indexes or `CREATE STATISTICS` objects, and needs a PostgreSQL 18 server.
- **Amazon RDS and Aurora:** the grants are documented, but not yet verified on a live instance. The security guide says which parts.

## Under the hood
- **Test matrix:** the snapshot code is tested against PostgreSQL 14, 15, 16, 17 and 18 with `pg_stat_statements` preloaded. `docker-compose.test.yml` starts them, and CI and the release job now start that same file instead of a single service container.
- **The canary test:** unique strings are planted in emails, names, statuses, JSONB, a column comment, query literals and query comments. The test fails if any of them, or any connection detail, reaches the artifact or `inspect`'s output, with positive and negative controls.
- **Other safety tests:**
  - every statement the collectors send is checked against an allow-list of catalog reads;
  - collection runs while another session holds `ACCESS EXCLUSIVE` on the tables;
  - two refreshes of an unchanged database must be byte-identical apart from their timestamp.
- **pg_dump in tests:** the real pg_dump 18 from the PG18 test container, through a shim on `PATH`.
- **New runtime dependency:** `ajv` 8.20.0, pinned to an exact version.
